# 框子 CLI（kuangzi）

## 这是什么

框子的命令行版：无界面、跑完即退，供智能体调用。与用户本机的 GUI 版共享同一份配置，快捷词表、日记路径、格式规则完全互通——CLI 写入的笔记/待办与用户日常热键速记进入同一套日记体系。

一句话定位：**写入、打开、确定性查询走 CLI；语义理解和总结是你的事。**

## 首次使用前：验证可用

每次会话首次调用前，先跑（零副作用）：

```bash
kuangzi --version
```

- 输出 `kuangzi cli v...` → 可用
- 命令不存在或报"框子未安装" → 不可用。CLI 依赖 GUI 版已初始化配置；未安装时提示用户先装 GUI 版（下载见仓库 Releases），**不要替用户猜路径写入**，也不要反复重试

## 核心心智模型

**写路径：直接调命令。** 用户说"记一下/待办/打开xx"，直接 `kuangzi note "..."` / `kuangzi todo "..."` / `kuangzi open xx --json`。格式、时间戳、追加位置全部由程序处理，不需要先读任何东西。

**读路径：命令优先，直读兜底。** 结构化查询（按日期看某节、待办状态、标签、行检索）一律用命令，输出是确定性的，不要读文件自己解析。只有"我写过什么关于试错的内容"这类语义模糊检索才由你直读文件——那是你的母语能力。

**路径永远问 CLI。** 日记按周期分文件（day/week/month），命名规则只有程序算得对。需要路径时 `kuangzi path today --json`，别自己拼文件名。

## 命令速查

### 写入类

| 命令 | 用法 | 说明 |
|---|---|---|
| note | `kuangzi note "文本"` | 速记：写入今日日记速记节，多行保留，自动加时间戳 |
| todo | `kuangzi todo "文本"` | 待办：写入待办节，`- [ ]` 格式 |
| stdin | `echo "文本" \| kuangzi note -` | 多行/长文本/特殊字符首选通道，无转义坑；todo 通用（参数 `-`）。**管道须 UTF-8**：Git Bash 原生满足；PowerShell 先 `$OutputEncoding=[Text.Encoding]::UTF8`；cmd 的 `echo 中文` 走 GBK 会乱码落盘，勿用 |
| attach | `kuangzi attach "文件路径"` | 附件归档：复制到附件目录（图片/视频/音频/文档，上限 200MB）+追加引用到今日日记 |
| done | `kuangzi done <关键词>` | 完成待办：全库扫描匹配的未完成项（正文或时间戳含关键词），原地翻转 `[ ]` → `[x]`；多匹配 exit 2 列候选 |
| send | `kuangzi send "按键串"` | 模拟按键（AHK Send 语法，如 `#v` 剪贴板历史、`#l` 锁屏）；全局快捷键为主 |

### 查询类

| 命令 | 用法 | 说明 |
|---|---|---|
| note | `kuangzi note [--date D] [--scope S]` | 无文本参数=查询态：查该日期的速记列表（时间+文本+来源设备） |
| todo | `kuangzi todo [--date D] [--scope S]` | 查询态：查该日期的待办列表（含完成状态） |
| daily | `kuangzi daily [--date D]` | 每日聚合：一次返回该日期速记+待办两表（默认今天） |
| todos | `kuangzi todos [--days N] [--open\|--done]` | 按时间窗查待办，跨设备全量；`--open` 只看未完成 |
| tag | `kuangzi tag <标签>` | 查含指定标签的行；精确匹配（`#选题` 不命中 `#选题库`，`#` 前须空白） |
| tags | `kuangzi tags` | 标签地图：所有标签+次数，按次数降序 |
| find | `kuangzi find <关键词>` | 全文行检索：子串匹配、不区分大小写；**自定义区/历史手写内容的语义检索全靠它** |

- 日期格式一律 `YYYY-MM-DD`（如 `--date 2026-09-17`），非法格式 exit 3；缺省今天
- **查询默认全量**：全部设备分区+不限时间；收窄才带 `--scope` / `--days`
- 周期混存无感：文件是日/周/月哪种周期、在哪个设备分区，查询一律按条目自身时间戳过滤

### 归档类

| 命令 | 用法 | 说明 |
|---|---|---|
| archive | `kuangzi archive [--week\|--month] [--go]` | 把写入区里上周期及以前的日记跨设备合并进归档区（**默认按月**） |

- **缺省即 dry-run**：只列归档计划不动文件；确认后加 `--go` 才真执行
- 真归档前自动备份源文件；产物落位后行级对账，对账不过不删源；当前周期文件一律不动
- 附件随迁进归档区只保留一份；归档后历史查询照常（归档区在 `--scope all` 扫描范围内）
- 用户说"归档日记/整理上月日记"：先跑 dry-run 给用户看计划，确认后再 `--go`

### 路径与打开类

| 命令 | 用法 | 说明 |
|---|---|---|
| path | `kuangzi path [today\|dir\|config]` | 零副作用路径查询：today=今日日记（带 `exists` 字段）、dir=日记目录、config=配置文件 |
| open | `kuangzi open "词\|路径\|URL"` | 明确的路径/网址直接打开；否则按用户快捷词表匹配（exit 2 会列候选） |
| today | `kuangzi today` | 打开今日日记（会开编辑器窗口） |
| dir | `kuangzi dir` | 打开笔记目录（资源管理器窗口） |
| new | `kuangzi new "文件名"` | 新建笔记（可省略 .md），创建并打开；同名已存在时报错不覆盖 |

### 个人直达 path（挂载管理类）

path 是用户的个人 PATH：把目录/文件挂进 `~/.kuangzi/data/kuangzi-app/path/`（.lnk 指针，文件不动），之后在框子输入框输名字直达——挂载目录的子文件递归可搜（node_modules/.git 等依赖目录剪枝）。

| 命令 | 用法 | 说明 |
|---|---|---|
| add | `kuangzi path add "D:\目录或文件"` | 挂载（建 .lnk），词=目标名；用户说"把xx加到框子path/挂载xx"即此命令 |
| rename | `kuangzi path rename 旧词 新词` | 改挂载词（仅目录挂载——文件挂载的词=目标文件全名，身份不可改） |
| remove | `kuangzi path remove <词>` | 移除挂载（删 .lnk）；path 根层手放的文件拒删，提示用户去资源管理器 |
| list | `kuangzi path list` | 列当前挂载与手放文件（词 → 目标） |

典型链路：用户"把 D:\客片 加到框子path，重命名为 婚纱客片" → `path add "D:\客片"` + `path rename 客片 婚纱客片"`。

#### 配置管理类（搜索引擎 / 快捷启动词）

用户说"以后搜索用这个网站""把这个软件挂到框子"时，直接改配置，不用让用户自己去设置页点。两张表就是设置中心里那两页：

| 表 | 命令 | 词的作用 | 生效入口 |
|---|---|---|---|
| 搜索引擎表 | `kuangzi engine` | 词 → URL 模板（`%s` 处填搜索词） | `/词 查询`、`kuangzi search 词 查询` |
| 快捷启动词表 | `kuangzi word` | 词 → 程序/路径/网址/动作 | `@词`、`kuangzi open 词`、`go` 兜底 |

四个子命令两表通用（缺省子命令 = `list`）：

| 命令 | 用法 | 说明 |
|---|---|---|
| list | `kuangzi engine list` | 列当前内容（词 → 目标） |
| add | `kuangzi engine add 知乎 "https://www.zhihu.com/search?q=%s" --home https://www.zhihu.com --desc "知乎搜索"` | 加条目 |
| remove | `kuangzi word remove 必应` | 删条目（不存在报 E_NOTFOUND） |
| rename | `kuangzi word rename 微信 威信` | 只改词，目标不变 |

`kuangzi word add` 的选项：`--type run|action|search`（缺省 run；search 的 URL 同样要 `%s`）、`--desc`、`--icon`、`--force`（同名覆盖，缺省报 E_EXISTS）。

**必须记住的三条**：

1. **engine 的 URL 必须含 `%s`**（搜索词占位，如 `https://www.bing.com/search?q=%s`）；漏了会 exit 3 被拒，别用别的占位符糊弄
2. **词或目标含空格必须加引号**：`kuangzi word add 微信 "D:\Program Files\WeChat\WeChat.exe"`；不加引号会被拆成多个参数，命令报用法错误（不会静默存半截路径）
3. **同名不覆盖**：已存在报 `E_EXISTS`，要改就 `remove` 后 `add`，或直接加 `--force`

**生效**：写入即落盘。宿主正在运行的话，用户下次唤起输入框（默认 Alt+Space）时会自动重载，当场可用——不需要让用户重启框子。改完可以告诉用户"直接就能用"。

## 路由与外部能力类

| 命令 | 用法 | 说明 |
|---|---|---|
| go | `kuangzi go "内容"` | 智能路由（与 GUI 输入框回车同一条链）：`@词`=快捷启动、`-内容`=待办、`/引擎 词`=指定引擎搜索、`$插件词`=插件调用，其余=兜底动作 |
| search | `kuangzi search "天气"` / `"百度 天气"` | 显式搜索：默认引擎或指定引擎（智能体首选，无前缀歧义；CLI 的搜索只开浏览器无返回结果，普通语义搜索仍由你自己做） |

## 输出协议

**所有调用都带 `--json`**（全局标志，可放任意位置），输出单行 JSON：

| 场景 | 形态 | 退出码 |
|---|---|---|
| 成功 | `{"ok":true,"action":"note","path":"日记完整路径"}` | 0 |
| 失败 | `{"ok":false,"code":"E_FAIL","msg":"原因"}` | 1 |
| 多候选 | `{"ok":false,"code":"E_MULTI","candidates":["A","B"]}` | 2 |
| 用法错误 | `{"ok":false,"code":"E_USAGE","msg":"原因"}` | 3 |

错误码表（与退出码一一对应）：`E_FAIL`=1 一般失败 / `E_SILENT`=1 静默失败（勿重试）/ `E_MULTI`=2 换精确词重试 / `E_USAGE`=3 修正命令。引擎级 `code` 可能是 `ERR_*`（GUI 错误码体系），按未知码处理、读 `msg` 即可。

关键约定：`ok` 是布尔；写操作成功必带 `path`；列表查询带 `count` 与结果数组；`time` 字段是条目时间戳、`date` 是条目日期（查询按它过滤）；`device`/`scopeDirs` 是来源标识。日期分组列表按时间排序呈现。

## 数据地图（直读文件时才需要）

配置在 `~/.kuangzi/data/kuangzi-app/config.json`：`VaultPath`（笔记库根）、`DeviceId`（本机设备标识，也是本机分区目录名）。

目录形状（跨端契约）：`<VaultPath>/kuangzi-data/<设备标识>/` 是本机写入分区，其下放周期文件（`2026-10-17_day.md` 等，连字符=名字、下划线=字段拼接）与 `attachments/`；`kuangzi-data/archive/` 是归档分区。**`kuangzi-data/` 下所有子目录读取端全扫、完全平权**（CLI 查询自动覆盖，直读无需特判）。

日记文件内部结构：**一个周期文件一个一级标题**，标题下两个二级节——待办（`- [ ] 时间戳` + 缩进正文）与速记（`- 时间戳` + 正文）；节标题是配置键（TargetTodoHeader/TargetHeader），默认 `## 框子待办` / `## 框子速记`。条目可带 meta 块（```meta 围栏，file/channel 键）。**按节取内容一律用节查询命令，程序按配置键定位最可靠；直读只用于语义检索。**

## 使用要点

1. 多行/长文本一律 stdin 通道（`kuangzi note -`），命令行参数传长文本有转义坑
2. `open` 的唤醒语义：应用已运行时是激活已有窗口，不是再开一个
3. 标签语法：`#` 前必须至少一个空白字符（行首 `#` 是标题不算标签）；一行可多标签；写在任何节都算
4. **不要用 CLI 做**：普通搜索/翻译/AI 问答（CLI 的搜索入口只是开浏览器，这些是你自己的能力）
5. 每日总结的正确姿势：`kuangzi daily --json` 取数，你负责归纳呈现（"今天记了 17 条速记、3 个待办，主要围绕xx主题"）；只关心某一节时用对应节查询命令
6. 定时任务/推送平台直接调 CLI 取数（如 `kuangzi todos --open --json`），输出是确定性的，格式化是平台的事
